# Life's Good Without Spying

[![build](https://github.com/lewisdoesstuff/lifesgoodwithoutspying/actions/workflows/build.yml/badge.svg)](https://github.com/lewisdoesstuff/lifesgoodwithoutspying/actions/workflows/build.yml)

A webOS homebrew app that switches off the surveillance stack on rooted LG
TVs: ad delivery, Automatic Content Recognition, and always-on voice capture.

![The app's main screen on an LG G4 running webOS 9](assets/screenshot.png)

> [!NOTE]
> **AI Generated Software Ahead**  
> While this is a pretty simple app, and tested on my TV, most of the code was generated by AI.

> [!WARNING]
> Supported on **webOS 4 and newer**. Only *tested* on **webOS 23 (9)** and **webOS 4.4** so far —
> webOS 5+ reported working okay

## Features

- Blackholes LG ad / ACR / telemetry domains to loopback by bind-mounting a
  generated `/etc/hosts` (per-category toggles, including separate
  crash/diagnostic, QuickSet, and optional ThinQ / companion, Home
  app-session and LG Content Store lists).
- Adds a separate LG Service Delivery Platform (SDP) category. Other domain
  blocks apply immediately, while SDP waits 60 seconds at boot so the TV can
  set its clock before those domains are added to the sink.
- Optionally sets the clock from NTP (`pool.ntp.org`) instead, so SDP can be
  blocked from boot.
- Stops the on-TV ad, ACR and telemetry daemons (`admanager`, `livepick`,
  `acr2`, `nudge`, `rdxd`, `uploadd`, `sportsalarm`).
- Targets listed LG voice and NLP services (`voiceinput`, `voiceconductor`,
  `nlpmanager`, `performer`) and the voice app. This does not disable
  microphone hardware or guarantee that other software cannot access audio;
  target availability and results vary by model and firmware. The remote voice
  key may stop working.
- Bind-mounts an inert stub over each target binary, so the Luna hub cannot
  respawn it (no polling loop).
- Answers calls to `admanager`, `voiceconductor` and `voiceinput` with a small
  stand-in, so apps and Settings don't hang waiting on them. It returns an
  all-zero ad ID and no voice languages; the real executables stay stubbed.
- With the ThinQ / companion toggle on, also stops the assistant and IoT
  daemons (`trigger_thinq`, `trigger_alexa`, `iot-client`, `iot-proxy`).
- Disabling protection puts the stopped services and the UPnP/SSDP daemons
  back, rather than leaving them down until a reboot.
- Optionally swaps `/usr/sbin/upnpd` for an inert stub, killing UPnP
  discovery both ways (breaks casting to the TV too).
- Wipes locally buffered ACR / speech-to-text files.
- Re-applies everything at boot through a Homebrew Channel `init.d` hook.
- Optional local DNS filtering routes ConnMan's IPv4 resolver through a
  reversible helper using the same marked domain list. A separate companion
  switch can disable ConnMan IPv6 when strict DNS coverage is required.

## Requirements

- A rooted LG webOS **(4+)** TV with the Homebrew Channel installed.
- Tested on: OLED65G45LW (EU), webOS TV 9.2.4, firmware 23.23.30.
- Reported working on webOS 5.

### webOS 4.x

- 4.x has no `busctl`, so the DNS filter reads ConnMan's settings with
  `dbus-send` instead.
- Protection may be off after a reboot. Some 4.x firmware never runs the
  Homebrew Channel startup hook
  ([webos-homebrew-channel#124](https://github.com/webosbrew/webos-homebrew-channel/issues/124)).
  Open the app and select "Update protection".

## Install

While this isn't currently published to the Homebrew Channel repo, you can add a custom repo to install it.  
Add: `https://raw.githubusercontent.com/lewisdoesstuff/lifesgoodwithoutspying/main/repo.json`  
Then install `Life's Good Without Spying` from the Homebrew Channel.

## Build

Needs `ares-package` ([setup](https://www.webosbrew.org/develop/guides/env-setup))
and `rsvg-convert` for the icons. `bun` is also required, to build the DNS
filter bundle.

```
./build.sh
```

Builds an `.ipk` plus its sha256 into `dist/`.

## Optional DNS filter

A separate helper lives in [`dns-filter/`](dns-filter/). It is a small
TypeScript DNS proxy with UDP/TCP forwarding, blocklist matching, and
acknowledged generation reloads. It consumes an atomically published domain
artifact derived from the app's marked hosts generation, so it sees the same
enabled blocks without treating `localhost` as blocked. The build always copies
the helper into the IPK; the separate `dns.filter` setting is what activates it,
and it defaults off. Its companion `dns.disable_ipv6` setting also defaults
off. See its [README](dns-filter/README.md) for the Bun build/test commands and
the ConnMan/firewall behavior.

The filter needs iptables NAT to divert port 53 into the helper. Some TVs ship
the `iptables` binary without the kernel's `ip_tables` module (seen on an LG B5,
webOS 25: `can't initialize iptables table 'nat'`). There the handoff can only
fail, so the app checks for NAT first: both DNS toggles and their status
cells are hidden, `set dns.filter on` is refused, and a setting already saved as on is
switched off at the next apply. There is no fallback for these TVs. Pointing
ConnMan's nameserver at the helper was tried and dropped (it fell back to the
real upstream on the emulator and broke DNS on webOS 6), and pointing
`resolv.conf` at it would only cover lookups the hosts file already sees.

## Install

With the TV reachable over SSH, either sideload it:

```
ares-install <device> dist/*.ipk
```

or push the `.ipk` to `/tmp` on the TV and install as root:

```
luna-send -i -f luna://com.webos.appInstallService/dev/install \
  '{"id":"ooo.lew.lifesgoodwithoutspying","ipkUrl":"/tmp/app.ipk","subscribe":true}'
```

(Uses `ssh -tt`: this TV's `luna-send` only prints on a TTY, and `-i`
subscribes forever, so wrap it in `timeout`.)

## Use

Open the app from the home screen. Enable whatever options you'd like, and choose 'Enable Protection',
and the main button cycles Enable / Update / Disable.

Enable, Update and Disable each run as a background job on the TV. The app
shows "Applying…" until the job ends, then prints its log. A job still running after 240 seconds
is stopped and reported as failed, so the app never waits forever. Over SSH,
`nospy-ctl.sh job` (or `status`) shows `job=running|done|failed|idle` and
`nospy-ctl.sh joblog` prints the last job's output.

## Uninstall

Uninstalling the app only deletes its folder. webOS gives the app no chance
to clean up first, so protection stays on. Turn it off before you remove it:

1. Open the app and select "Disable protection". This unmounts `/etc/hosts`
   and the stubs, starts the stopped services again, rolls back the DNS
   filter and removes the boot hook.
2. Uninstall the app from the Homebrew Channel.

Your settings and the log stay in `/var/lib/webosbrew/`, so a reinstall picks
them up. To remove them too, run as root:

```
rm -f /var/lib/webosbrew/lifesgoodwithoutspying*
```

Already uninstalled without disabling? A reboot undoes most of it, but two
things outlast it: the boot hook link, left pointing at nothing, and, if
"Turn off IPv6" was on, ConnMan's IPv6 setting, which stays off. For IPv6,
reinstall the app, select "Disable protection" and uninstall again. Do that
before you delete anything: the rollback reads the files above, and the app
only offers "Disable protection" while the boot hook link exists. Otherwise
remove the link:

```
rm -f /var/lib/webosbrew/init.d/50-lifesgoodwithoutspying
```

## Notes

- **LG SDP / clock sync** is enabled by default. webOS normally gets its clock
  from the `X-Server-Time` header returned by a regional `*.nextlgsdp.com`
  service, not NTP. SDP is omitted from the sink for the first 60 seconds, then
  blocked; all other enabled domain blocks apply immediately. SDP is also used
  for LG service initialization, device registration/authentication, app
  metadata and EULA/notice data, so the grace period permits more than clock
  synchronization. Disabling this category leaves its domains out of the
  generated blocklist, including the initial generation. Re-apply protection
  after changing the setting to remove SDP entries from an older generation.
  The LG Content Store needs SDP: with this category on, the store stops
  opening once the grace period ends (error -102, or `P6.48.SZ` on some
  firmware). Leave it off if you use the store.
- **Clock from NTP** (`clock.ntp`, default off) sets the time from
  `0-2.pool.ntp.org` with a small SNTP client run under the TV's Node, then
  hands it to webOS through `com.webos.service.systemservice/time/setSystemTime`,
  falling back to `date -s`. (On webOS 9 with network time on, `setSystemTime`
  accepts the call but leaves the clock alone, so `date -s` is what works.)
  With both this and the SDP category on, SDP is blocked as soon as protection
  applies, with no grace period. At boot the network may not be up yet, so the
  sync retries in the background for up to 10 minutes; the log records the
  result. It needs `node` on the TV, and UDP port 123 out.
- **QuickSet remote codes** use `www.ueiwsp.com` for periodic remote-control
  code lookup. This is kept in the separate `domains.quickset` category,
  which defaults off, so enabling ad blocking does not disable QuickSet by
  default. Turn it on only if you do not need remote setup or replacement
  remote controls.
- **Home app sessions** (`domains.wiselg`) blocks the regional `*.tv.wiselg.com`
  hosts, which upload app-session records (app IDs, user number, start/end
  times). The same hosts serve Home recommendations, previews, sports and
  channel-map metadata, so the category defaults off.
- **LG Content Store** (`domains.lgrecommends`) blocks the hosts the store
  needs: `*.app.lgwebostv.com`, which serves its interface, and the regional
  `*.lgrecommends.lgappstv.com` recommendation hosts. These used to be in the
  Telemetry and Home dashboard categories, where they stopped the store opening
  (error 202 or -102). With them in their own category, which defaults off,
  the other categories no longer break the store. The store also needs SDP.
- **Service stand-ins.** The hub still lists a stubbed service, so a call to it
  gets no reply and Settings or apps can hang. `nospy-luna-stub.js` registers
  three of those service names and answers the calls they need, without reading
  any ID or touching audio; the self-test reports whether each one is running.
  It needs `node` on the TV.
- **The domain sink is host-based.** The self-test's `getent` and `curl`
  checks only prove that the generated `/etc/hosts` is visible to commands
  using the local resolver. Some webOS services use their own DNS path,
  including DNS-over-TLS, and may bypass `/etc/hosts`; an un-stubbed service
  could therefore still connect. The voice and ad process checks are the
  stronger signal for the protections this app controls.
- **The DNS filter toggle is opt-in.** It uses the atomically published domain
  artifact derived from the marked generated hosts list, routes ConnMan's IPv4
  nameserver through a local helper, and blocks LAN access to the helper
  listener. The separate `dns.disable_ipv6` companion switch controls whether
  the handoff also changes ConnMan IPv6; when it is off, IPv6 is preserved and
  IPv6 DNS may bypass the helper. When it is on, the handoff also points
  `resolv.conf` at `127.0.0.1` only, as ConnMan's `::1` proxy stops answering
  once IPv6 is off. Disabling the DNS filter restores the
  original nameserver and restores IPv6 only if the handoff had changed it.
  Direct DNS, DNS-over-TLS/HTTPS, and custom resolvers remain outside its
  scope; if the helper exits, the handoff fails closed until re-applied or
  rolled back.
- **DNS helper limits:** the optional helper checks the requested name but does
  not inspect CNAME targets returned for allowed names. Its locally generated
  blocked-name replies carry at most an empty EDNS OPT record, without options
  such as DNS COOKIEs; some clients that require them may retry or fail. See
  `dns-filter/README.md` for details.
- You don't need the update block option if you've got the option set in the Homebrew Channel.
